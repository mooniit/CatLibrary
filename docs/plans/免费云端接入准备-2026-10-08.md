# 免费云端接入准备

用户已确认目前没有 Supabase 云端项目，先准备免费云端接入。

## 当前状态

现有 Android 包使用电脑本地 `127.0.0.1:54321`。ADB reverse 只能验证手机到电脑的本地连接，不能代表离开电脑后可用。用户已于本轮告知创建云端项目，项目 URL 和公开密钥尚待取得；没有验证云端或执行远程迁移。本地现有数据库、账号和资产继续保留。

当前控制台获取方式：进入项目，**Integrations → Data API** 复制 Project URL；**Settings → API Keys** 复制 Publishable key（`sb_publishable_`），旧版则选 anon/public。顶部 Connect 对话框通常也提供两项。Secret key、service_role、数据库密码及会话令牌不用于客户端公开配置、不在聊天索取。路径依据 [官方 API 文档](https://supabase.com/docs/guides/api) 和 [公开密钥说明](https://supabase.com/docs/guides/getting-started/api-keys)。

## 已备好的接入工具

- `scripts/supabase-cloud.example.json`：只有项目 URL 和公开密钥的空模板。另存为忽略的 `.tooling/cloud-phone-defines.json` 后填写；`SUPABASE_ANON_KEY` 字段也接受新的 `sb_publishable_...` 密钥。
- `scripts/cloud-config.cjs`：检查 URL、公开密钥类型与配置字段。拒绝 `sb_secret`、`service_role`、用户会话 JWT、测试参数和含凭据的 URL；旧 anon JWT 的项目标识不匹配时拒绝。密钥的实际有效性由服务端检查，离线格式检查不能证明有效。
- `scripts/build-phone.ps1`：构建前执行上述检查，错误配置在 Flutter 构建开始前被拒绝。现有本地安装配置仍可使用，会明确标为 local。
- `scripts/cloud-preflight.cjs`：生成有序迁移 SHA-256 清单。指定云端配置与 `--probe` 时，只读取公开 Auth 设置及 REST API 描述；禁止跟随重定向，不注册用户、不调用业务写入、不输出密钥或响应正文。HTTP 可达、匿名登录开关和 API 描述通过后，也不等于业务迁移、原身份迁移或真机同步已通过。

在项目根目录运行：

```powershell
# 尚未创建项目时，生成本地准备清单。
node scripts/cloud-preflight.cjs

# 创建免费项目并填写公开配置后，只读检查云端。
node scripts/cloud-preflight.cjs --config .tooling/cloud-phone-defines.json --probe
```

检查记录写入忽略的 `.tooling/cloud-preflight-<时间戳>.json`，不会覆盖现有配置、安装包或数据库。未传配置显示 `awaiting_cloud_project`；联网检查失败以非零退出码结束。

## 免费项目设置与迁移命令

在自己的 [Supabase 控制台](https://supabase.com/dashboard)创建 **Free** 组织下的项目，不选择付费升级或付费附加项。开启匿名登录，允许新用户注册；保存公开 HTTPS URL 与 publishable key。数据库密码留在自己的密码管理器或本机交互提示中，不发到聊天。免费项目可能因一周不活跃而暂停，恢复后需重新检查定时任务与业务补偿，不能承诺全天候运行。

以下命令已对现有 CLI 的帮助核对，但因为尚无云端项目，**没有执行登录、绑定或远程推送**：

```powershell
$catLibraryCli = Join-Path $PWD '.tooling/supabase-cli/node_modules/@supabase/cli-windows-x64/bin/supabase.exe'
& $catLibraryCli login
& $catLibraryCli link --project-ref <控制台的项目标识>
& $catLibraryCli db push --linked --skip-vault --dry-run

# 核对目标及迁移清单后，执行正常迁移；不导入 seed。
& $catLibraryCli db push --linked --skip-vault
```

本次清单有 **45 个迁移文件**，包含正式商品价格、120 秒编辑权、画作绑定与旅行返程。M0 样例表也在既有历史迁移中，保持迁移历史完整，但不导入样例用户或测试 seed。`test_grant` 迁移仅增加库存来源类型，不给任何家庭自动发放月轨资产。无需为远程接入改动房屋坐标或素材。

远程迁移后需检查三个 cron 作业：`study-midnight`、`family-daily-settlement`、`cat-travel-returns`，以及私有 `task-photos` 存储策略。客户端公开只读预检查无法证明这些管理状态，需使用本人登录后的控制台或 CLI 核对。

## 接入顺序

1. 用户在自己的 Supabase 账号下创建免费项目。通过控制台自行登录、设置数据库密码；不向聊天发送管理令牌、数据库密码或 service_role。公开接入仅需要项目 HTTPS URL 和 anon/publishable key。
2. 在本机 CLI 完成用户自己的登录后，绑定指定项目，先执行 `supabase db push --dry-run` 核对现有迁移清单，再执行正常迁移。不得运行远程 reset，也不导入本地测试 seed 或测试时钟服务。
3. 核对匿名登录、私有照片存储、RLS、家庭权限及旅行返程定时任务。两个独立云端测试成员先验证购买、保存、并发和断网回执，不使用原手机资产作为故障测试数据。
4. 单独处理现有匿名账号与家庭资产迁移。新云端项目不会自动识别本地项目的匿名会话；不得只更换 URL 后自动新建身份。需核对原账号、家庭、库存来源、钱包和布局版本，完成可恢复迁移后才给原手机切换配置。
5. 将公开 URL/密钥保存在忽略的 `.tooling/` 配置文件，通过 `scripts/build-phone.ps1 -DefinesFile <配置文件>` 构建正常 APK。保留本地配置与上一版安装包供核对。
6. 手机覆盖安装，验证账号与资产保留；拔掉 USB，使用实际 Wi-Fi/移动网络完成双人同步后，才能记录“远程在线通过”。

## 已实施的前置保护

网络状态基于真实 HTTP 响应；超时与服务端错误分别处理。设置页提供重新连接入口；恢复连接后重新读取钱包、猫咪与失败的房屋数据，编辑草稿不被后台刷新覆盖。

身份守卫在首次连接时核对记忆身份及已有 SQLite 账户缓存。已有身份丢失会话或身份不匹配时暂停连接，不再自动创建替代匿名账号。身份守卫 12 项与网络状态 5 项回归测试通过；当前 Flutter 全量 116 项通过，静态分析无问题。此记录不代表云端部署完成。
