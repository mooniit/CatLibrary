# 免费云端接入准备

用户已确认目前没有 Supabase 云端项目，先准备免费云端接入。

## 当前状态

现有 Android 包使用电脑本地 `127.0.0.1:54321`。ADB reverse 只能验证手机到电脑的本地连接，不能代表离开电脑后可用。项目尚未创建、远程迁移尚未执行；本地现有数据库、账号和资产继续保留。

## 接入顺序

1. 用户在自己的 Supabase 账号下创建免费项目。通过控制台自行登录、设置数据库密码；不向聊天发送管理令牌、数据库密码或 service_role。公开接入仅需要项目 HTTPS URL 和 anon/publishable key。
2. 在本机 CLI 完成用户自己的登录后，绑定指定项目，先执行 `supabase db push --dry-run` 核对现有迁移清单，再执行正常迁移。不得运行远程 reset，也不导入本地测试 seed 或测试时钟服务。
3. 核对匿名登录、私有照片存储、RLS、家庭权限及旅行返程定时任务。两个独立云端测试成员先验证购买、保存、并发和断网回执，不使用原手机资产作为故障测试数据。
4. 单独处理现有匿名账号与家庭资产迁移。新云端项目不会自动识别本地项目的匿名会话；不得只更换 URL 后自动新建身份。需核对原账号、家庭、库存来源、钱包和布局版本，完成可恢复迁移后才给原手机切换配置。
5. 将公开 URL/密钥保存在忽略的 `.tooling/` 配置文件，通过 `scripts/build-phone.ps1 -DefinesFile <配置文件>` 构建正常 APK。保留本地配置与上一版安装包供核对。
6. 手机覆盖安装，验证账号与资产保留；拔掉 USB，使用实际 Wi-Fi/移动网络完成双人同步后，才能记录“远程在线通过”。

## 已实施的前置保护

网络状态基于真实 HTTP 响应；超时与服务端错误分别处理。设置页提供重新连接入口；恢复连接后重新读取钱包、猫咪与失败的房屋数据，编辑草稿不被后台刷新覆盖。

身份守卫在首次连接时核对记忆身份及已有 SQLite 账户缓存。已有身份丢失会话或身份不匹配时暂停连接，不再自动创建替代匿名账号。身份守卫 12 项与网络状态 5 项回归测试通过；当前 Flutter 全量 116 项通过，静态分析无问题。此记录不代表云端部署完成。
