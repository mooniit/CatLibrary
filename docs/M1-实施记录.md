## 第一批交付：T05 页面接入与 T06 自动身份、初始钱包

- 普通启动自动复用本机 Supabase 会话；没有会话时匿名建立身份，无注册登录页。
- 调用 bootstrap_identity，由服务端根据 auth.uid() 原子建立个人钱包和初始赠送流水。初始为 30 喵喵币、0 鹰镑、0 宝石，重复、并发请求不重复赠送，不重置已有余额。
- 钱包及流水启用 RLS；客户端只能读取本人的数据，不能直接增删改余额或流水。RPC 不接收用户编号，避免替他人初始化/操作。
- 首次连接展示等待页；失败提供重试，成功进入默认猫窝并展示后端余额。开发预览为显式入口，标注无真实资产，不把预览余额当成成功。
- 保留四个导航、猫窝内商店/相册/设置及阅读占位。计时奖励、家庭、领养仍未正式接入；现有领养样例仍标注为内存试用。

## T07 家庭与邀请码（2026-09-22 已接入）

猫窝新增「家庭与邀请」入口。无家庭时可创建单人小屋，或直接输入邀请码提交加入申请；不要求先建另一间小屋或领养。邀请码由服务端生成随机 32 位十六进制串，邀请人可复制。申请者看到等待确认状态，邀请人在页面刷新后可同意或不接受，成员关系以服务端结果为准。

创建、申请、审批均通过受身份约束的 RPC 操作。三张家庭表启用 RLS 并关闭客户端直接读写；RPC 只返回本人相关家庭/申请。只有邀请人可审批并读取邀请码和待处理申请。成员最多两人、一个用户只属于一个家庭；用户锁及家庭行锁串行化并发审批，重试创建/审批不会重复加入。没有退出或家庭合并功能，个人钱包不合并。显示名仍待定，当前使用用户编号区分申请者，不擅自创建姓名规则。

验证结果：

- 数据库 30/30 通过，其中新增家庭 10 项：无家庭起点、幂等建屋、直接申请、申请不自动加入、防自批、邀请人审批、重复审批、第三人拒绝及直接写权限。
- 真实本地 HTTP 三身份流程通过；同时审批两条申请只加入一人，另一条可拒绝；既有家庭不可加入另一家庭，共同成员看不到邀请码和审批队列。
- 客户端 21/21 回归通过；静态检查无问题。首次组件测试滚动定位遇到多个 Scrollable，已限定主列表并复测通过。
- 模拟器邀请人页面 + 独立 HTTP 申请者完整链路通过：实际建屋、读取邀请码、提交申请、页面审批、申请者读取两人家庭。不是两台物理设备。初次界面检查被模拟器 System UI 无响应弹窗遮挡，选择 Wait 恢复后重试通过。
- 证据：evidence/m1-family-*。本轮没有重装手机，没有改动货币规则或生成画面。

运行入口：按前述本地配置运行应用 → 猫窝 → 家庭与邀请。申请者和邀请人通过右上角刷新获取最新状态；本轮未实现邀请推送。用于端到端验证的模拟器小屋目前已有一个独立测试成员。

## T08 真实领养与家庭猫咪管理（2026-09-22）

猫窝「猫咪管理」已替换旧内存试领养，读取真实家庭猫咪记录，显示每只猫的名称、预设外观、登记主人及本人剩余名额。无家庭时提供创建/加入小屋入口，不自动创建另一间小屋；无云身份的开发预览不再允许假领养。旧 adoption_sheet.dart 已移除。

免费领养通过 adopt_cat RPC 执行，主人从 auth.uid() 获取，不接受客户端传 owner_id。每人最多两只，同一外观只能领养一次；同一家庭名称不能重复，不同成员可以各自领养同外观猫咪，合计最多四只。两套预设使用 black_short / light_long 标识，无新画面或性格设定。

数据库表关闭客户端直接读写，cats_state 只返回当前家庭；领养持有家庭行锁，并由唯一约束保护外观及重名。相同用户、外观和名字的重试返回原记录，不重复创建；失败时页面保留输入且不假显示成功。没有改名、转移主人、删除猫咪等未要求功能。

验证：
