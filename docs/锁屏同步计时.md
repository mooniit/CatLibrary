# 锁屏同步计时（2026-09-21 实施）

用户于 2026-09-18 确认需要锁屏同步计时。此增量先提供 Android 通知栏/锁屏计时显示；iPhone 尚缺 Mac/Xcode 和真机，未实现或验收其锁屏展示。不改变计时奖励、跨日结算或货币规则。

## 行为

- 点击开始时申请通知权限；允许后显示「自习计时中」，以本次开始时间建立系统 chronometer。
- 通知静音、无振动，显示通用计时信息，点击返回应用。锁屏是否展示仍服从用户的系统通知设置。
- 结束计时、保存失败、冷启动恢复以及已检测到六小时上限时移除计时通知。
- 权限拒绝不阻止应用内计时，并显示锁屏通知未开启的说明。
- Android 使用同进程 specialUse 前台服务，START_NOT_STICKY；不在异常进程重建时自行重新计时，不申请保持唤醒锁或修改电池优化设置。

## 验证范围

客户端测试覆盖权限允许/拒绝、开始显示、结束移除及冷恢复清理；本轮共 16 项客户端测试通过，静态检查无问题。Android arm64 原生构建成功并安装到一加 Android 16；原生系统 chronometer 与应用使用同一开始时间、结束清除通知与服务、force-stop 清除通知、冷恢复不误启四项实测通过，见 evidence/m0-oneplus-notification.json。用户于 2026-09-21 回复「可以看到」，已确认一加锁屏通知可见；数字持续递增未单独确认。系统无障碍抓取通知栏时返回 could not get idle state，未将失败的抓取记为通过。

通知显示层不负责保存可靠学习检查点，不代表之前七分钟锁屏观察中的落盘限制已经解决。原生六小时移除包含定时检查和通知超时设置；系统深度休眠、系统停止服务与实际六小时上限仍需专项实测。Q07、跨零点入账与其他未确认事项保持待定。

## 实现依据

- [Android Notification.Builder](https://developer.android.com/reference/android/app/Notification.Builder)：系统 chronometer、通知可见性和超时设置。
- [Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)：specialUse 类型与声明；后续若公开上架需按届时要求验证分发配置，本轮未发布。
- [Android 通知权限](https://developer.android.com/develop/ui/views/notifications/notification-permission)：运行时通知权限与用户控制。

## 六小时边界快速验证（2026-09-21）

一加 Android 16 执行 integration_test/lock_screen_timer_test.dart，1 项通过：起点注入为距六小时上限约 12 秒，确认原生通知先存在、15 秒后移除；未来起点被拒绝且不显示通知。通过只读方法通道查询当前应用通知，不修改设备时钟或自习数据库。日志：evidence/m0-oneplus-notification-boundary.txt。

该结果仅证明设备清醒状态下的原生边界行为，不等于连续六小时、锁屏六小时或深度休眠通过。
